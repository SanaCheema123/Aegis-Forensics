# Aegis Forensics integration audit — 16 November 2026

**Assessment: conditionally ready for a controlled offline FYP demonstration; not verified ready for an unrestricted demonstration of every advertised capability.** The core evidence, rules, trained network inference, chronology, lexical search, saved scan review, monitoring and validated export workflows were demonstrated. Security-log access, trusted embedding search and successful local LLM generation remain blocked. Two original case chains fail verification and were preserved unchanged.

## Scope and evidence

Actual headless Google Chrome walkthroughs were performed through the Chrome DevTools Protocol, with file uploads, native text/key input, navigation, selectors, monitoring controls and real downloads. This was not a backend-only audit. Most functional writes were confined to a separate project copy under [the audit run](audit_artifacts/integration_20261116_063044). Its final four modified production files were byte-compared with the real project. Original-project browser checks were limited to read-only navigation and the invalid-default-case upload guard, which rejected the upload before saving evidence.

Backend probes, automated tests and native Windows read-only checks supplement the browser evidence; their coverage is distinguished below. Some intermediate browser scripts had timing or locator assertion failures. Product failures were reproduced and fixed; final PASS claims refer to the specified successful captures and artifacts, not every intermediate capture.

## Remaining limitations, reproduction and recommendations

1. **Invalid original histories:** start the real project, choose its default `CASE-2026-001`, and upload a harmless CSV. Verification blocks it. Choose a known verified case explicitly for the demonstration. Investigate original provenance or restore an independently verified original backup through a separately reviewed recovery procedure; do not rehash altered entries to make them appear authentic.
2. **Global versus scoped review:** the isolated run deliberately contains `CASE-INTEGRATION-UNRELATED-BAD` as a negative fixture. Opening saved evidence with “All case histories” blocks. Choosing `CASE-DEMO-VALID` verifies only that explicitly named history. This is not a global latest-scan claim. A case without an upload record for the exact source remains blocked.
3. **Unavailable LLM:** use Investigation → Investigation report → Generate report with the installed Ollama service. The observed UI request times out after 120 seconds and returns a labeled template. A successful warm local generation must be separately verified before advertising an LLM demonstration. Do not download another model as an automatic workaround.
4. **Unavailable embeddings:** run a search and expand Technical Details. It identifies lexical mode and the missing reviewed manifest. Enabling embeddings requires a reviewed local revision, complete safe-artifact/config/tokenizer hashes and then a separate embedding-path test. Installing optional vision dependencies does not provide that provenance.
5. **Windows coverage:** Security-log reads fail in the current non-elevated context even outside the managed sandbox. Defender/CIM reads succeed outside the sandbox, so sandbox-only access errors are not classified as application defects. If Security coverage is required for the presentation, arrange an approved read-capable test environment in advance and retest; this audit did not change permissions.
6. **Long reports and broad heuristics:** real script-block messages produced a 189-page report for 55 findings. Preserving complete records is correct but slow to render and re-export. Prefer a small prepared file/CSV demonstration; budget time for laptop exports. PowerShell/script/service events are review signals, not proof of compromise. Further performance or detection-policy redesign is outside this fix.
7. **Packaging/startup:** use the exact canonical command in the demo guide. There is no working `main.py` launcher, no fresh-install test and no fully pinned dependency lock. Preserve the tested venv for the presentation and plan a separate reproducible packaging task. Existing Streamlit width deprecation warnings should be handled in a future compatibility pass.
8. **Trust boundary:** no automated audit can make unanchored histories independently authentic. Export guards were retained, and an invalid or legacy report can still be blocked even when its text is visible. Historical findings and reports are not retroactively rewritten by these changes.

Proceed with a rehearsed, scoped **offline evidence / trained network inference / UTC timeline / lexical search / deterministic reporting** demonstration using verified cases. Do not describe successful embeddings, successful LLM generation, full Security-log coverage or complete endpoint protection as verified capabilities of this audit.
